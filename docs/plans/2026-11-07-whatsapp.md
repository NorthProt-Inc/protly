# WhatsApp Web Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use execute-flow to implement this plan task-by-task.

**Goal:** On `web.whatsapp.com`, protly works the way it does in Instagram DMs: partner messages are translated to
Korean in place (past: replace, new: below, per thread), Korean typed in the message box becomes a translation preview
on Enter (Enter sends, Esc undoes, Alt+Enter retries with Opus, language chip), English is polished when the Polish
flag is on, the floating thread panel holds the per-chat settings and memo, Alt+T is owned by the adapter, and own
sent messages show the Korean original on hover.

**Architecture:** The Instagram content core (`src/content/main.js`, `outgoing.js`, `panel.js`, `dom.js`) is made
site-neutral by a small **site adapter** object. The Instagram-specific parts (thread id from the URL, thread root
and viewer check, message reading, composer lookup, card anchor, names in badge text) are reached through it.
`src/content/instagram.js` and `src/content/whatsapp/site.js` each export `SITE` plus `start()`, and each loader's
single `getURL` import points at its adapter, so `tests/war.test.js` keeps deriving every web-accessible list from
the import graph. Background, prompts and storage are reused; WhatsApp thread state is keyed `t:wa-<hash>`, and the
router refuses `wa-` ids from Instagram.

**Tech Stack:** Chrome MV3, plain ES modules (no build step for content scripts); `node:test` + jsdom 30.1.3.

Spike facts: `docs/spike-notes-whatsapp.md` (2026-11-07, two reads). Branch `feat/whatsapp`, worktree
`../protly-whatsapp`, base `f3d3623`. Plan reviewed 2026-11-07 (PASS WITH CHANGES, all twelve changes applied here).

## Facts this plan relies on

- The URL is always `/`; no chat JID exists in the DOM. The chat's identity is the header title
  `#main header [data-testid="conversation-info-header-chat-title"]`. The one header read had no `<img>`, but names
  likely render emoji as `<img alt>` like bubbles, so the title is read with `textOf` too.
- Chat switch replaces `#main`; rows are never reused across chats. A fresh `#main` shows 1 row, then the history.
- Row `[data-testid^="conv-msg-"]`; text = first `[data-testid="selectable-text"]` outside
  `[data-testid="quoted-message"]`; own message = `[data-testid="msg-meta"] [aria-label]` trimmed equals `Read`,
  `Delivered`, `Sent` or `Pending`. No `data-icon` marks status (only `tail-in`/`tail-out`, first of a run only).
- **Emoji in bubbles are `<img alt="😀">`**; `innerText` drops them. Emoji in the composer are Unicode text.
- Composer `#main footer div[contenteditable="true"][role="textbox"]`, Lexical; `setComposerText` works unchanged.
- No Trusted Types on WhatsApp: the panel's `shadow.innerHTML` stays.
- `tests/war.test.js:30` reads the **first** `getURL('...')` of each loader as the entry and requires the WAR list to
  equal that entry's import graph plus the fonts, and WAR `matches` to equal the content script's.
- `dom.js:1` imports `selectors.js`, so the WhatsApp graph includes the Instagram selectors file; that is fine.
- The main working tree holds uncommitted WIP in `CLAUDE.md`, `docs/security-review.md`, `host/protly_host.py`,
  `src/generic/instance.js`, `src/lib/native.js`, `src/lib/prompts.js`, `tests/generic-instance.test.js`,
  `tests/hostile-page.test.js`, `tests/native.test.js`. This branch touches only `tests/hostile-page.test.js` of
  those (one call site). Task 6 handles the merge.
- Test commands: one file `node --test tests/<file>.test.js`; all `npm test`.

## Decisions

1. **Thread id = `wa-` + cyrb53 hex of the header title**, computed synchronously (the Enter guard and `live()` run
   inside keydown). With `#main` present but no title found, the id is the fixed `wa-untitled` (so the guard and the
   "thread not found" badge still work; see Task 3). Accepted limits:
   - Two chats with the same title share settings, memo and sent originals.
   - A rename starts a fresh thread state.
   - A title that changes while the chat is open (contact sync shows the phone number, then the name; a group
     rename) tears down and re-inits; `staleSig` matches the same rows, so the re-init waits the full ~10 s, during
     which a Hangul Enter is held with the "Still loading" toast. Documented, not mitigated.
2. **Direction by the English status label.** Non-English WhatsApp UI: own messages count as partner (translated,
   wrong roles in context), never a missed send guard. Known gap; no locale table now.
3. **Group chats**: everyone but the viewer is `partner`, as on Instagram.
4. **Prompts unchanged.** The any-site box already sends the "Instagram direct messages" system prompt on every
   site (`tests/prompts.test.js:161-164`); nothing needs the wording.
5. **No `host_permissions` for WhatsApp** (Instagram's is under review, security review R9). Add only if the live
   check needs it.
6. **UI text:** popup gets a `WhatsApp` switch (default on) and the label `Polish English on Enter (Instagram,
   WhatsApp)`; options heading `Defaults for new Instagram threads` becomes `Defaults for new chat threads`;
   manifest description and README name WhatsApp Web. `CLAUDE.md` and `docs/security-review.md` are not edited on
   this branch (main-tree WIP); a one-line CLAUDE.md update follows the merge.
7. **Out of scope:** WhatsApp Desktop, status/channels/communities, media captions, non-English UI direction, prompt
   tuning.

```js
// src/content/whatsapp/site.js
// Every WhatsApp Web DOM assumption lives here (spike: docs/spike-notes-whatsapp.md).
import { start as run } from '../main.js';
import { textOf } from '../dom.js';

export const SEL = {
  threadRoot: '#main',
  title: 'header [data-testid="conversation-info-header-chat-title"]',
  messageRow: '[data-testid^="conv-msg-"]',
  messageText: '[data-testid="selectable-text"]',
  quote: '[data-testid="quoted-message"]',
  meta: '[data-testid="msg-meta"]',
  composer: 'footer div[contenteditable="true"][role="textbox"]',
};
const OWN_STATUS = new Set(['Read', 'Delivered', 'Sent', 'Pending']); // English UI only (plan Decision 2)

// cyrb53, a sync 53-bit string hash (public domain): the id is needed inside a keydown handler.
export function cyrb53(str) { /* standard cyrb53, 14 lowercase hex chars */ }

const mainOf = (doc) => doc.querySelector(SEL.threadRoot);
// textOf, not textContent: an emoji-only name ("🔥🔥") must not fall to wa-untitled, "Mom" and "Mom ❤️" must differ.
export const chatTitle = (doc) => {
  const el = mainOf(doc)?.querySelector(SEL.title);
  return el ? textOf(el).trim() || null : null;
};

// Never null while a chat is open: a title selector miss must still give the badge and the Enter guard.
export function threadIdFor(doc) {
  if (!mainOf(doc)) return null;
  const t = chatTitle(doc);
  return t ? `wa-${cyrb53(t)}` : 'wa-untitled';
}

export function senderOf(row) { /* 'me' when msg-meta holds an OWN_STATUS aria-label, else 'partner' */ }
export function textElOf(row) { /* first messageText not inside a quote, or null */ }
export function readMessages(root) { /* rows with a body; text = textOf(textEl).trim(); skip empty */ }

export const SITE = {
  key: 'whatsapp', name: 'WhatsApp',
  threadId: () => threadIdFor(document),
  findThreadRoot: (doc) => (chatTitle(doc) ? mainOf(doc) : null), // no title: waitForThread times out -> badge
  readMessages,
  findComposer: (doc) => mainOf(doc)?.querySelector(SEL.composer) ?? null,
  cardAnchor: (c) => c.closest('footer') || c.parentElement,
};
export const start = () => run(SITE);
```
